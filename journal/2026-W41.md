# 2026-W41

## 2026-10-11 (Sun) — v4.21.1 and v4.21.2: variadic field source; releases like ssql

v4.21.1: `FieldCompleter.getFilePathFromContext` read the source flag
only as a string, so `FieldsFromFlag("FILE")` over a Variadic FILE fell
back to the `<FIELD>` hint. ssql made `from parquet` FILE variadic (one
stream from several files or a glob) and `-columns <TAB>` lost its
names. The first element of a list now names the fields
(`TestFieldCompleter_VariadicSource`).

v4.21.2: Ross: "we own autocli as well so we should add a changelog and
version constant etc so that it is released in the same way as ssql".
`CHANGELOG.md` (Keep a Changelog, v4.0.0 onward from the tag messages,
v0–v3 summarised from the old CLAUDE.md history), `Version` in flag.go
is now the release's own version (it said 4.0.0 from v4.0.0 to v4.21.1 —
v4.21.1 itself was tagged that way, and a tag is never moved, hence a
patch release), and `TestVersionMatchesChangelog` gates both: Version
equals the newest entry, and on a clean checkout any v* tag on HEAD names
Version. The tag check skips a dirty tree, because between releases HEAD
still carries the previous tag while the next is being prepared (the
gate's first run failed for exactly that reason). Watched it fail on the
v4.21.1 source (Version "4.0.0"). The steps are in CLAUDE.md "Release
Process".

### shell v0.5.1 and ssh v0.1.15: the same release process

Ross: "yes do the same for shell and ssh". Each nested module now has a
