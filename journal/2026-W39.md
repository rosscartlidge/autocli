# 2026-W39

## 2026-09-22 (Tue) — `-arg VALUE`: the flag form of a positional

Motivation is ssql's DFC134 (pipelines as data): a flag's arguments are
bound by count and never inspected, so `where -if name eq -invert` is safe
to build from untrusted data; a POSITIONAL has no arity, so `include name
-generate` flips ssql into code generation (CWE-88). Ross's fix: give every
positional a flag form, in autocli, once.

What landed: `ArgFlag = "-arg"` (flag.go). `Parse` appends the next element
verbatim to the current clause's positionals, so handlers cannot tell the
two forms apart and typed/variadic/global/local positional matching is
untouched. `findFlagSpec` answers a package-level hidden one-argument spec
for the name on every command, which is what made completion, help-at and
cursor analysis work without each learning about it: they already skip by
arity. The two places that did NOT skip by arity were rewritten onto one
helper, `positionalValues` (completePositional's counter, and
field_completer's positional lookup, which had been counting flag
arguments as positionals). `isArgFlagValue` walks FORWARD so that an
`-arg` which is itself another flag's argument (`-if name eq -arg`) is not
mistaken for the real thing; it gates the "partial starts with - so
complete flag names" shortcut, so `-arg -de<TAB>` completes the slot.
Builders panic on declaring `-arg`/`+arg`; `+arg` on a line is an error;
exact match, so ssql's `-arg-max` is unaffected. `-spec-json` root gains
`positionalFlag`; help ARGUMENTS sections gain a two-line note.

Why not `--`: it is a mode switch, it cannot coexist with `-`/`+`
separators, and it is already RemainingArgs (ssql's `from ssh HOST --
PIPELINE`).

Verified: arg_flag_test.go (sabotaging the Parse branch fails 8 tests);
ssql built against this checkout via a scratch `-modfile` reads columns
named `-generate`, `-desc`, `-`, `+` and a file named `-weird.csv` with no
ssql change. Side effect worth knowing: `from -arg csv` means a FILE called
csv, not the csv subcommand.
